# ฟังก์ชันที่ขาดหรือควรเพิ่มสำหรับ Teerayut

รายการนี้เป็นข้อเสนอจากการตรวจโค้ด Teerayut ปัจจุบัน **ยังไม่ได้เพิ่มฟังก์ชันเหล่านี้** ผู้ใช้ต้องเลือกขอบเขตก่อนเริ่มทำ การปรับหน้าตาทั้งสองงานไม่ได้ทำให้ฟังก์ชันหรือโค้ด cloud ของ Project ถูกคัดลอกไป Teerayut

## ตัวเลือกที่ได้ประโยชน์เร็ว

| ฟังก์ชัน | สถานะปัจจุบัน / สิ่งที่เพิ่ม | ความซับซ้อน | AWS เพิ่มจากแผนเดิม |
| --- | --- | --- | --- |
| บันทึกงานที่สนใจ | ยังไม่มีรายการ Saved Jobs แยกจากใบสมัคร เพิ่มปุ่มบันทึกและหน้ารายการของตัวเอง | เล็ก | ไม่จำเป็น ใช้ฐานข้อมูลเดิม |
| บันทึกร่าง Logbook | แบบฟอร์มมีข้อมูลระหว่างกรอก แต่ยังไม่มีการกู้ร่างหลัง refresh/ปิดหน้า เพิ่ม draft ที่แยกตามผู้ใช้ | เล็ก-กลาง | ไม่จำเป็น หากเก็บใน browser หรือฐานข้อมูลเดิม |
| วันเวลาและลิงก์สัมภาษณ์ | มีสถานะ INTERVIEW_SCHEDULED แต่ยังประสานวันเวลา/สถานที่ภายนอก เพิ่มข้อมูลนัดหมายและการแสดงผล | กลาง | ไม่จำเป็นสำหรับบันทึก/แสดงนัดหมาย |
| แจ้งเตือนภายในเว็บ | มีการแสดงสถานะเมื่อโหลดข้อมูล แต่ยังไม่มี Notification inbox/read state สำหรับสถานะใหม่ ข้อเสนอและผลอนุมัติ | กลาง | ไม่จำเป็นสำหรับแบบพื้นฐาน ใช้ API/DB และ polling ได้ |
| ตั้งเป้าชั่วโมงฝึกงานตามหลักสูตร | เป้าหมายปัจจุบันคงที่ 400 ชั่วโมง เพิ่มการตั้งเป้าและสรุปความคืบหน้าตามค่าที่เลือก | กลาง | ไม่จำเป็น แต่ต้องตกลงว่าใครมีสิทธิ์กำหนดเป้า |

ถ้าเลือกทำเพียง 2-3 อย่างก่อน แนะนำ **Saved Jobs + นัดสัมภาษณ์ + แจ้งเตือนในเว็บ** เพราะช่วยตั้งแต่ค้นหางานจนถึงติดตามผล และต่างจากการเปลี่ยนหน้าตาอย่างชัดเจน

## ฟังก์ชันที่จำเป็นเมื่อเปิดใช้จริง หรือทำให้ระบบใหญ่ขึ้น

| ฟังก์ชัน | หมายเหตุ |
| --- | --- |
| ลืมรหัสผ่าน / ยืนยันอีเมล | ยังไม่มี ต้องมี token ที่หมดอายุและช่องทางส่งอีเมลจริง การส่งอีเมลอาจต้องใช้ผู้ให้บริการเพิ่ม จึงควรตกลงก่อนให้สอดคล้องกับเป้าหมายใช้ AWS เท่าที่จำเป็น |
| ส่งออกข้อมูล CSV หรือรายงานเพิ่มเติม | มีรายงานประเมินที่พิมพ์ได้อยู่แล้ว ไม่ควรนับว่าขาด report ทั้งระบบ CSV/รายงานสรุปเป็นส่วนเพิ่ม |
| ผู้ดูแลมหาวิทยาลัยและการอนุมัติจบฝึกงาน | UNIVERSITY_ADMIN เป็น enum แต่ยังไม่มี workflow ที่ใช้งานได้ ต้องกำหนดสิทธิ์และเกณฑ์อนุมัติก่อน เป็นงานขนาดใหญ่ |
| OCR Transcript / แนะนำงานตามทักษะ | ยังไม่มีจริง ต้องเตรียมไฟล์ตัวอย่าง การตรวจความถูกต้องและผู้ใช้ยืนยันผล รวมถึงค่าใช้จ่ายของบริการที่เลือก OCR ไม่ใช่การรับรองว่าเอกสารหรือเกรดเป็นของจริง |

## สิ่งที่ไม่ควรสับสนกับฟังก์ชันใหม่

การตั้ง CORS/secrets, private-file authorization, migration, production Docker, TLS และ network permissions เป็นงานแก้/เตรียมระบบเดิมก่อน deploy ไม่ใช่ wishlist ของฟังก์ชันใหม่ โดย Teerayut ยังไม่ได้รับชุด cloud hardening ของ Project จึงต้องตรวจงานเหล่านี้แยกก่อนนำ Teerayut ไปเปิดสาธารณะ

สิ่งที่มีแล้วและควรคงไว้: ค้นหางาน/ตัวกรองที่มี, สมัครพร้อมเอกสาร, HR pipeline, ยืนยันที่ฝึกงานเพียงแห่งเดียว, cancellation review, daily logbook, mentor sign-off, rubric และ printable evaluation report
