## Existing behavior corrected

- Reports, logbook review/approval, rubric submission, and application status changes now check the owning student or company.
- Academic identifiers, email, and GPA in public profiles are available only to the student or an employer with a related application.
- Approved daily logs cannot be edited or deleted through the API. Approval and student writes serialize on the same student row.
- Calendar-day uniqueness also covers legacy log records that contain a time of day.
- Hours, logs, and evaluations are scoped to their placement application. Previous placements are excluded from current totals.
- Concurrent applications and offer commitments recheck the workflow inside a locked transaction. Final application states cannot be overwritten through the HR status endpoint.
- Posting deletion refuses to erase internship placement history; closing a posting remains available through the existing edit form.
- Mobile navigation no longer consumes most of the page width. The existing menu opens/closes, supports Escape, restores focus, and closes on navigation.
- Homepage search uses actual active postings, applies its existing filters, displays empty/error/loading states, and preserves search through login.
- The printable evaluation report counts approved hours and includes the student's name. Text was corrected to describe implemented behavior rather than unavailable certification/AI guarantees.
- Registration validates its supported roles and creates account/profile atomically. GPA/year and rubric inputs are validated server-side. Academic year matches the existing 1–6 form range.
- Upload limits agree at 5MB; unsupported extension/MIME pairs and oversize uploads return JSON validation errors.
